# DOOM (2016, Nintendo Switch) → нативный Android: журнал порта

Хронология от первой минуты (27.10.2026 13:06) до вечера 28.10.2026 (23:06). Время московское (UTC+3); в транскриптах UTC.
Источники: три сессии Claude (`cd6a372e…`, `14c676cf…`, `185a70f7…`; вторая и третья начинаются копией хвоста предыдущей),
сводки компакций, `docs/research/*.md`, память проекта, код. Подробности по каждому багу — [BUGS_AND_FIXES.md](BUGS_AND_FIXES.md),
переключатели и инструменты — [SWITCHES.md](SWITCHES.md), разведка — [RECON.md](RECON.md), заимствования — [THIRD_PARTY.md](../THIRD_PARTY.md).
Пометка «(не подтверждено)» — нет прямого свидетельства в логах/словах хозяина.

## Итог одной строкой
За ~34 часа: игра со Switch (NSO ARM64 + NVN) исполняется на телефоне нативно, без эмуляции CPU; меню, кампания, звук,
сенсорное управление, гироскоп, аим-ассист работают; графика исправлена в главном (зелень, туман/декали/TAA, тени); fps в бою
**~5 → ~47** (медиана), в больших сценах Марса ~40–43. Открыто: дыры при включённом GS-куллинге, Turnip, 60 fps.

## Цель и принципы (заданы хозяином в начале)
- Подход как у d2r-mobile: исходный ARM64-код игры исполняется напрямую + офлайн-патч NSO + HLE `nn::` + NVN→Vulkan.
  Цель — сохранение игры на Android (`doom-port-project` в памяти).
- «Не переусердствуй как кодекс» (27.10 13:18): брать максимум из d2r-mobile, не строить AOT/эмулятор (опыт D2R, где Codex
  ушёл в регистровый AOT runtime, который хозяин забросил).
- Все файлы проекта — в одной рабочей папке (Claude Desktop не видит другие папки).
- Шейдеры только офлайн, «если на лету — это и накладки по перфомансу и эмуляция почти».
- Целевое устройство №1 — Snapdragon 8 Gen 3 / Adreno 750 (Mi 14 Ultra), а не новейшие флагманы; позже (19:55) — «как можно
  больший спектр устройств».
- Из nxnative/nx2android (MIT) «бессовестно заимствовать всё, что лучше для нашего порта DOOM», с атрибуцией; «не всякую
  универсальную ересь».
- Онлайн «вырубить нафиг, как в Diablo».

## Фаза 1. Патчер, HLE, NVN→Vulkan, шейдеры, первый кадр (27.10, ~14:00–16:00)

- **Патчер NSO** (`dm/tools/patch_nso.py`, `DM_TARGET=android`): x18/TLS/svc/cntpct через слоты TSD, таблицы переходов со
  словными смещениями, `mov sp, x18`. Эквивалентность 29 238 мест — 0 расхождений (`equiv.py` в Unicorn, `--jobs 12`).
- **Хост** — форк d2r-mobile (`src/`, ветка `doom`, `DM_GAME=doom` → `DM_GAME_DOOM`), D2R-фичи огорожены (`doom_stubs.c`).
  HLE для SDK 6.4: bcat, fs (SetAllocator/ReadFile/GetDirectoryEntryCount/CommitSaveData), socket/nifm/ssl/account/friends/err/
  web/time/vi, csrng через getrandom, hid (JoyDual, DebugPad, SixAxis), AudioRenderer (PCM16 48 кГц).
- **NVN** (`hle_nvn.c`, блок DOOM): Buffer*, MemoryPool*, TextureHandle/Address, RegisterImage, fast clear, WriteTexels,
  SetSize3D, GetLevels, ReportValue; swizzle/depth-stencil mode/reduction — заглушки с логом.
- **Шейдеры** офлайн: `doom_shader_jobs.py` → `build_dmsh_xlate_doom.py` → `dmsh_vk_doom.py` → **863 `.xgs`, 0 ошибок**.
- **APK «DOOM Mobile»** (`org.doom.port`) — хозяин заметил, что APK назывался как D2R (14:25). Данные: `/sdcard/Download/DOOM
  Mobile/{romfs, dm/out, dm/shaders, dm/env}`, нужен «доступ ко всем файлам» (FUSE не даёт shell-файлам доступ в
  `/sdcard/Android/data`).
- **Блокер первого present**: игра стояла на `Initializing renderSystem media`. Ключ — `SyncWait` для sync без fence возвращает
  `ALREADY_SIGNALED`.
- **~15:57** хозяин: «рендерер мерцает, но дошёл до меню лицензионного соглашения. Но управления пока что нет». Bink-ролик зеленел.

## Фаза 4. Производительность, ночь 27→28.10 (22:52–06:45)

- Замер: ~5 fps, submit_cpu ≈ 148–160 мс, GPU ≈ 66–78 мс, 460–530 проходов, 720–836 draw; профиль: other 109 мс, hash 29 мс
  (полная перезаливка VT-кэшей 89/33 МБ). simpleperf: рендер-потоки заняты ~22 %, ядра 0.9 ГГц — **ждём, а не считаем**.
- 23:35 после первой правки: «имхо лучше вообще не стало». 23:52 хозяин: «постарайся сделать максимально близко к общей памяти
  Switch, если на Qualcomm + Adreno это возможно».
- Сделано (каждое за переключателем, BUGS §3.1): GPU-indirect, storage chain, ленивые барьеры, частичная перезаливка VT,
  zero-copy на AHardwareBuffer (у Adreno 750 нет `external_memory_host`; `work/zc_test` доказал когерентность), early-Z,
  depth-feedback без разрыва, пролог-копии, фенсы без лока. Сопутствующие крэши: «Storage alias allocation not found» →
  `gpu_merge_pending`; OOM при 24 кусках арены → 6; индексы из AHB роняли драйвер → снапшот.
- **00:39** «в игре, по-прежнему шакально и лагово». Хозяин оставил телефон на ночь: «отключи блокировку экрана... сама потом
  обязательно убивай процесс игры, чтобы не перегреть телефон... До утра чтобы было 60 fps» (время сообщения ≈00:40, не
  подтверждено). Блокировку экрана **не трогали** (правило: не менять настройки безопасности, не вводить PIN); автовход
  `tools/doom_enter.sh` + `phone_pad.sh`.
- **≈04:00** итог ночи: 17–22 fps в бою, CPU трансляции ~10 мс, GPU 30–45 мс, ~80 проходов. Основной шейдинг 15–17 мс,
  GS-prepass ~6.6 мс.
- Perfetto без root (`tools/perf_trace.sh`, `perfetto/doom.cfg`, `analyze.py`): горячие потоки спят 14–22 тыс. раз по 80–300 мкс
  (3.3–5.7 с из 7.9 с) → timer slack 1 мкс (`DM_TIMERSLACK_NS`); yield back-off и same-core handoff (132 с ожидания на 80 тыс.
  передач) — гипотезы для A/B.
- Таймстемпы NVN: 614.4 МГц (`ns*384/625`), а писались 19.2 МГц → DRS игры видел GPU-время в 32 раза меньше.
